# Project datasets

Both folders are needed: one supplies clean reference images, and the other supplies the official corrupted versions.

| Folder | Contents | Use in the final study |
|---|---|---|
| `cifar-10-batches-py/` | Original CIFAR-10 Python batches: five training batches, `test_batch`, and metadata | The final loader reads `test_batch` for clean images and labels at severity **0**. The training batches are not used to train the three final classifiers. |
| `CIFAR-10-C/` | Official pre-generated corruption arrays such as `gaussian_noise.npy`, `brightness.npy`, and `gaussian_blur.npy`, plus `labels.npy` | Supplies corrupted images at severity levels **1–5**. These pixels are loaded directly, not generated by our custom corruption functions. |

## How they connect

Each corruption array contains five blocks of 10,000 images, corresponding to severities 1–5. Within each block, image IDs follow the original CIFAR-10 test ordering. `src/cifar10c_loader.py` checks label alignment and pairs each selected clean image with its corrupted versions. All images are 32 × 32 pixels before model-specific preprocessing.

The clean image supplies the reference attribution map. IG and Grad-CAM maps from the corrupted versions are compared against it to calculate attribution loss, gain and retention-weighted Wasserstein distance. Keep both dataset folders to reproduce collection.

Final candidate IDs are recorded in `results/expanded_cifar10c_5000dev_2000test/development_manifest.csv` and `fresh_test_manifest.csv`; the data folders contain the full datasets, not only those selected candidates.
